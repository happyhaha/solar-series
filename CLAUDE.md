# Solar Series — портфолио marlindev.ru

Личный сайт-портфолио Рахима Муратова на Astro + Tailwind v4.
Цель: показывать кейсы.

## Архитектура

- **Astro 5** (статический режим), **Tailwind v4**, MDX-кейсы через Content Collections.
- **Дизайн-токены** — единственный источник: `src/styles/tokens.css`. Tailwind v4 `@theme`-переменные автогенерируют утилиты (`font-heading`, `tracking-display`, `text-prose-body`, ...).
- **Шрифты, цвета, межбуквенные интервалы, line-height** — только через токены. Не хардкодить hex/`font-family`.
- **Кейсы** — `src/content/cases/*.mdx` со схемой в `src/content.config.ts`. Динамический роут `src/pages/cases/[slug].astro`.
- **Скрины интерфейса** — аннотируются компонентом `<AnnotatedShot>` (`src`, `alt`, `spots[]`: `{n,x,y,title,text}`, x/y в % по картинке). Десктоп: боковая легенда на уровне пинов; мобила: крошечный пин + плашка справа. Из-за импорта компонента кейсы и переведены на MDX.
- **Длинный текст** — оборачивать в `<Prose>` (`src/components/Prose.astro`). Применимо для оферты, политики, тела кейса.
- **Контейнер по умолчанию** — `w-full px-6 md:px-12`. Внутренние блоки ограничиваются `max-w-*`.

## Команды

```bash
npm run dev      # дев-сервер с HMR (http://localhost:4321)
npm run build    # SSG-билд в dist/
npm run preview  # превью продакшен-билда
```

Для CSS/разметки достаточно HMR. Билд гонять только при правке `content.config.ts` (регенерация типов) или перед деплоем.

## Структура кейса

Frontmatter (`src/content/cases/*.mdx`):

```yaml
title: Полное название              # обязательно, идёт в <title> страницы
titleLines:                          # опционально, переопределяет рендер h1
  - Первая строка
  - Вторая строка
subtitle: Короткий подзаголовок      # опционально, мелкий текст над h1
client: Название клиента             # пока не выводится — см. TODO
year: 2024
role: Роль на проекте
services: [список]
stack: [список]
cover: /img/cases/foo.jpg
summary: 1-2 строки, идёт в правую колонку шапки
links:
  live: https://...
  repo: https://...

draft: false
```

# Workflow написания контента

Кейсы готовятся в папке `drafts/` и переносятся в проект ассистентом.

## Структура драфта

```
drafts/
  case-one/
    case-one.md        # frontmatter + тело кейса
    cover.jpg          # обложка шапки (16:9)
    card.jpg           # превью для карточки на главной (4:3, опц.)
    screenshot-1.png   # любые иллюстрации внутри текста
```

## Правила оформления драфта

- Пути к картинкам пиши **относительно папки драфта** (`cover.jpg`, `screenshot-1.png`). Не указывай `/img/...`. Ассистент при переносе подставит финальный путь.
- В теле картинки оформляй стандартным markdown: `![подпись](screenshot-1.png)`.
- Frontmatter желательно полный (см. «Структура кейса» выше), но обязательны только `title`, `summary`, `order`. Недостающее ассистент заполнит и уточнит.
- Если нужна разбивка заголовка кейса на строки — поле `titleLines: ["Первая", "Вторая"]`. Иначе h1 берётся из `title`.

## Команда переноса

Когда драфт готов: пишешь «обнови case-one из drafts» (или аналогично по slug).

Ассистент тогда:

1. Читает `drafts/<slug>/<slug>.md` (или `index.md` если нет именованного).
2. Копирует все картинки из `drafts/<slug>/` в `public/img/cases/<slug>/`.
3. Создаёт / обновляет `src/content/cases/<slug>.mdx`, переписывая пути картинок на абсолютные (`/img/cases/<slug>/<file>`).
4. Отчитывается о результате: что скопировано, что подправлено, чего не хватает.

## Git

Папка `drafts/` лежит в репозитории как резерв исходников. Если решишь её не коммитить — добавь в `.gitignore`.
