# Аннотации скриншотов интерфейса — дизайн

Дата: 2026-05-17
Статус: утверждён (подход выбран через прототип `/mock/annotate`)

## Задача

Большие скрины интерфейса платформы в кейсах (особенно длинные —
обсуждение урока 1920×3345, дашборды) нечитаемы: непонятно, куда смотреть.
Нужна навигация по скрину — указатели на места + короткие пояснения.
Решение должно работать на десктопе и мобиле, переиспользоваться во многих
кейсах, иметь стабильную вёрстку, жить в файлах (не БД), сборка статическая.

## Выбранный подход (вариант A, выверен в прототипе)

**Десктоп (≥1024px):** скрин слева, справа колонка-легенда. Каждый пункт
легенды абсолютно спозиционирован на уровень `y` своего пина
(`translateY(-50%)`). На скрине крупные серые круглые пины с номером.

**Мобила (<1024px):** боковая легенда скрыта. На скрине крошечные пины;
у каждого справа маленькая тёмная плашка с пояснением (стрелка слева на
пин). Плашка всегда справа от пина.

**Цвета/типографика:** пин — приглушённый серый `#9aa0a6`, цифра
`font-weight:500`, `tabular-nums`, `line-height:1` (строго по центру).
В компоненте подвязать к токену `--color-accent` не нужно — серый намеренно
неконтрастный; цвет вынести в одну переменную компонента.

## Архитектура

### 1. MDX-инфраструктура

- Установить `@astrojs/mdx`, добавить интеграцию в `astro.config.mjs`
  (`integrations: [mdx()]`).
- Переименовать все кейсы `src/content/cases/*.md` → `*.mdx` (5 файлов:
  case-one..case-five). Контент не меняется — Markdown валиден в MDX.
- `src/content.config.ts`: glob `pattern` `**/*.md` → `**/*.{md,mdx}`.
- Обновить `CLAUDE.md`: правило «кейсы — `.md`» → «`.mdx`».

### 2. Компонент `src/components/AnnotatedShot.astro`

Props:

```ts
interface Spot { n: number; x: number; y: number; title: string; text: string }
interface Props {
  src: string;
  alt: string;
  url?: string;          // если задан — обёртка в хром браузера (как галерея)
  spots: Spot[];
  loading?: 'lazy' | 'eager';
}
```

- Вёрстка варианта A целиком внутри компонента (десктоп-легенда +
  мобильные плашки + пины). CSS — scoped в компоненте, не в Prose/global,
  чтобы вёрстка была стабильной и не зависела от внешних правил.
- `x`/`y` — проценты по картинке; пины и плашки позиционируются от них.
- Брейкпоинт 1024px (как в прототипе).
- Опциональный браузерный хром повторяет разметку существующих мокапов
  (`BrowserFrame`-стиль), включается при наличии `url`.
- Цвет пина — одна CSS-переменная в компоненте.

### 3. Применение в `case-one.mdx`

Аннотировать только 3 реальных скрина:

- `lesson-discussion.png` — в галерее «Интерфейс» (сейчас в мокап-хроме).
- `admin-dashboard.png` — в разделе «Со стороны администратора».
- `admin-students.png` — там же.

Заменить эти `<img>`/мокап-блоки на `<AnnotatedShot>` с массивом `spots`.
Координаты прописываются после просмотра каждого скрина. Для
`admin-dashboard` переиспользовать выверенные в прототипе значения:

```
1 x58 y16  Состояние потока
2 x63 y33  Очередь проверки
3 x60 y58  Ближайшие занятия
4 x58 y84  Кто давно не заходил
```

Плейсхолдеры `lms-*` (lms-home/course/schedule/profile) не трогать —
остаются обычными мокапами в галерее.

### 4. Прототип

`src/pages/mock/annotate.astro` оставить как референс (не удалять).

## Границы (что НЕ делаем)

- Не аннотируем плейсхолдеры `lms-*` (фейковые картинки).
- Не трогаем другие кейсы (case-two..five) кроме переименования в .mdx.
- Не меняем содержимое текста кейсов.
- Не делаем редактор координат / drag-and-drop — координаты руками в MDX.

## Критерии готовности

- `npm run build` проходит, `/cases/case-one` рендерится статически.
- 3 реальных скрина показаны через `<AnnotatedShot>`: на десктопе легенда
  на уровне пинов, на мобиле — плашки справа от крошечных пинов.
- Остальные кейсы открываются как раньше (контент не изменился).
- CLAUDE.md и `content.config.ts` соответствуют новому формату.
